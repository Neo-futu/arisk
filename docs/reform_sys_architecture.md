# 改造ARisk Platform 阿雷斯 智能风控与投资分析系统 架构与设计文档

文档目的：明确“小而美、可迭代、搭积木式”的智能风控与投资分析系统架构。以数据底座为基础，以投资风控为核心，预留并逐步接入交易，通过模块化、Agent化、CLI/API化实现业务落地。

## 項目目錄 
arisk文件夾

## 核心设计理念

1. **小而美，垂直深入**：不贪图大而全，参考彭博 Port，将独立业务（数据管理、组合管理、估值、风控）做完整再累加。
2. **贝莱德模式本地化**：参考 Aladdin，以投资、风险、数据、模型、工作流为核心，交易管理预留展位并可编辑模拟。
3. **搭积木式开发**：模块化、Agent化、CLI/API化。用户通过上传、聊天或参数输入，系统能完成独立业务逻辑并落地。
4. **前沿交互体验**：页面采用“三区+AI”布局（参数区、数据/报表区、图表区、右侧 AI Chat 区），满足金融业务与前沿 AI 融合需求。
5. **灰度上线机制**：系统配置控制模块菜单前端显示，开发测试验证完毕才对用户可见，避免半成品污染体验。
6. **最小闭环逐步可用（数据底座先行）**：优先攻克“市场数据”与“组合持仓”两大核心模块，建立坚实的数据底座。有了稳定数据后再逐步开发业务逻辑代码，确保系统始终具备可操作的最小闭环。
7. **业务逻辑与 Agent 渐进式累加**：底层代码与风控计算引擎保持高确定性与稳定性，上层 Agent、Port 组合管理及风控模块以搭积木方式逐层叠加，避免无底座开发导致的系统无序与不可靠。
8. **市场数据与组合持仓的可编辑与数据库联动**：市场数据与组合持仓虽然最终目标是自动对接外部系统，但在迭代开发阶段，系统必须支持界面可视化编辑，并直接链接与操作底层数据库表，提供完整的数据管理与维护能力，以保障业务逻辑的快速调试与验证。

## 系统分层与目录架构设计

1. **展示与交互层**
   - **数据底座重构**：统一页面布局为【参数选择区】+【数据/报表区】+【图表展示区】。
   - **AI Chat 侧边栏**：右侧固定/可隐藏的 AI Chat 框，全局可用；同时总菜单有专属 Agent Chat 页面统筹所有 workflow。
   - **动态菜单**：通过系统配置（开关）决定菜单项是否前端显示。
   - **模擬組合與真實組合**:支持模擬組合與真實組合，並設置基準組合，可以為模擬組合添加證券，並每日估值計算損益，損益暫時可編輯並預留與估值系統估值比較。

2. **Agent编排与API层 (6_entry + aiagent + backend)**
   - 支持聊天指令、API 调用、CLI 触发。传入信息通过路由分发到具体模块完成业务逻辑。
   - SQL 资产化：`2_processing` 中的 SQL 不仅是查询，同时可供 API 调用和 AI Agent 大模型上下文训练/参考使用。

3. **计算与业务规则层 (2_processing + 3_skills)**
   - **目录结构调整**：在 `2_processing` 下新建 `indicators` 目录，与 `mmf` 平行，存放非 mmf 的风控指标 SQL 文件。
   - **源文档管理**：`mmf-eva-report` 目录下的源文档作为凭证留存，但数据已解析入库，业务流转基于入库数据。
   - **核心引擎**：提供 VaR、WAM/WAL、集中度、归因等确定性计算。

4. **数据与连接层 (4_mcp + 1_datastorage)**
   - 建立基础数据、市场数据、组合数据、静态数据、风控规则等维护能力，支持数据库表直连与手工增删改查（CRUD）。

## 核心功能模块与菜单清单

*(注：每个模块配置“是否前端显示”开关，逐个验证后上线)*

### 1. 数据管理中心 - *地基*
- **1.1 数据库表维护**：基础数据、静态数据、组合数据、市场数据的数据库表直连维护与可视化增删改查。
- **1.2 源文档管理**：`mmf-eva-report` 等已入库源文档的归档查看与追溯。
- **1.3 风控规则维护**：阈值、事前/事中/事后规则配置。

### 2. 组合与交易管理 - *业务起点*
- **2.1 组合列表与驾驶舱**：Dashboard 展示所有组合的基本盘与状态。
- **2.2 持仓管理与数据库联动**：界面可操作、可编辑调整组合持仓，改动实时同步至底层数据库，为行研、风控验证提供可控输入源。
- **2.3 交易管理 (展位)**：交易流水管理界面，可录入模拟交易，后续对接真实交易数据。

### 3. 市场行情与指标探索 - *数据源*
- **3.1 市场行情界面**：宏观数据、个券行情、收益率曲线等展示。
- **3.2 指标探索引擎 (类似 DataJungle)**：选择指标、国家、周期、数据源，动态生成折线/对比图表，并提供 API 导出。
- **3.3 市场行情界面与数据维护**：支持接入外部数据源，同时提供可编辑界面以维护宏观数据、个券行情、收益率曲线等数据库记录。

### 4. 组合估值与损益 - *验证闭环*
- **4.1 估值报表**：基于可编辑持仓与市场行情，生成每日估值表。
- **4.2 损益分析**：阶段损益归因，验证持仓与交易变动的结果。

### 5. 投资与风险分析 - *核心大脑*
- **5.1 投资组合分析**：资产配置、期限结构、行业/信用暴露。
- **5.2 风险指标监控**：基于 `2_processing/indicators` 计算的 VaR、波动、回撤等。
- **5.3 事前事中风控**：交易前合规检查、阈值预警；组合构建模拟器。
- **5.4 事后风控报表**：标准化日报、月报输出。

### 6. Agent 与工作流中枢 - *智能化*
- **6.1 全局 Agent Chat**：贯穿所有 workflow 和业务的对话入口。
- **6.2 指标解读与验证**：结合已入库数据，由 Agent 验证和解释报表与波动。
- **6.3 定时与编排**：自动化运行估值、风控、报表流程。

## 前沿交互设计规范

所有业务页面强制遵循以下布局，确保前沿 AI 体验：
- **左侧/顶部（参数区）**：组合选择、时间区间、指标筛选等参数。
- **中部（数据/图表区）**：上半部分为数据表格/明细（支持实时编辑与数据库联动），下半部分为动态图表/报表。
- **右侧（AI Chat 区）**：固定边框，可隐藏。针对当前页面的数据、图表，直接提问追问、生成解释、提供下一步建议。

## 搭积木式落地节奏

采用“一波一波，做完一块上一块”的策略，自发主动创业。

### 阶段一：建立市场数据与持仓底座（最小闭环入口）
1. **打牢数据底座**：优先接入【市场数据】与【组合持仓】模块，跑通基础数据的自动对接与入库。
2. **可编辑与数据库联动**：在开发阶段实现市场数据和持仓数据的界面可编辑功能，直接绑定底层数据库表，支持手工修正与测试数据维护。
3. **跑通内控验证**：运行“产品评估报告”流程，验证基础数据一致性与数据维护能力。
4. **交互规范落地**：上线“参数区 + 数据区 + 图表区 + 右侧 AI Chat”四区标准布局。
5. **交易展位与模拟**：上线可编辑持仓与模拟交易录入界面。

### 阶段二：业务逻辑沉淀与估值闭环
1. **引入行情与指标分析**：完善【市场行情与指标探索】（类似 DataJungle），提供动态图表与 API。
2. **逻辑代码开发**：基于“市场数据+组合持仓”开发稳定的估值与损益计算逻辑代码，完成数据闭环验证。
3. **指标解耦沉淀**：落地 `2_processing/indicators`，将风控计算逻辑抽取为独立 SQL/代码组件。
4. **上线基础 DashBoard**：提供组合列表与基础风控监控页面。

### 阶段三：风险垂直深入与 Agentic AI
1. 上线【投资与风险分析】：完善事前/事中/事后风控制度与功能。
2. 模块全面 Agent 化：通过 API/CLI，聊天即可驱动业务模块。
3. 灰度释放所有菜单，形成“小而美可用”的风控模块矩阵。

## 汇报结论

本方案以**“小而美、可验证、搭积木”**为核心。
1. **数据先行，可编可维**：以“市场数据”与“组合持仓”为起点，对接外部系统的同时保持界面可编辑与数据库表联动，保障前期开发与运维的灵活性。
2. **聚焦落地，不贪大求全**：从数据维护、组合持仓、估值损益开始，形成最小闭环，逐个模块完整落地验证后再向上累加,逐个完整落地上线。
3. **交易预留，模拟闭环**：预留交易管理展位，通过界面可编辑持仓与模拟交易录入，提前打通前中后台的数据验证链路，通过界面可编辑持仓与模拟交易，打通验证链路。
4. **前沿交互，AI 深度赋能**：落地“参数区+数据/报表区+图表区+右侧 AI Chat”四区标准布局，让每个业务页面都成为 Agentic AI 的沉浸式操作台。
5. **逻辑解耦，渐进叠加**：保持底层业务逻辑与风控计算代码的高确定性与独立性，上层 Agent 编排与 Port 高阶风控模块以“搭积木”方式渐进式叠加，避免架构混乱。
6. **演进路径，自发增强**：先满足内控合规与基础风控需求，再垂直深入做透资产定价与风险归因，最终构建自发主动、具备高度可扩展性的 Agentic AI 智能风控平台。
